# A500 付费墙安全审查(2026-06-12)

> Fable 两周作战计划 Week1-D3。A500 是薪酬域消费端,VIP 状态问 ATA100 中心。
> 范围:VIP 门禁是否后端有效。结论先行:**A500 的 VIP 增值内容是前端遮罩,数据已下发到浏览器,可被绕过查看。**

## 发现(P2):VIP 报告字段是前端 CSS 遮罩,非后端门禁

- 查询接口 `/api/queries`(server.js:132)只要登录就能调,**不校验 VIP**;`fetchIsVip` 只在 `/api/vip/status`(server.js:112)被调用,纯粹返状态给前端。
- 完整薪酬报告(含 VIP 增值字段 `industryAnalysis` 25 个细分行业 + `highEarnerTraits` 谈薪筹码)**一次性全部返回到前端**(server.js:229)。
- 前端 `VipOverlay.jsx` 对非 VIP 用 `blur-[6px]` + `select-none` + 半透明蒙层"遮住"这两块——但**被遮内容就在 DOM 里、在网络响应里**。非 VIP 用户打开浏览器开发者工具看 Network 响应,或删掉那个 blur 的 CSS class,就能看到完整 VIP 内容。

### 危害定级
- **P2 而非 P1**:被遮的是增值内容(行业细分 + 谈薪筹码),核心薪资数字(月薪/年薪/职级阶梯)本就免费可见。所以是"VIP 增值内容可被技术手段白看",不是"核心付费功能免费"。
- 与文件下载付费墙不同:A600 台账、A800 文档是**后端 gate**——不下发文件,绕不过;A500 是**数据已下发、前端遮罩**,能绕。

### 修复建议(不在本次擅改,理由见下)
后端在非 VIP 时**不下发**这两个字段:`/api/queries` 返回前,若 `fetchIsVip(req)` 为假,删掉 `report.industryAnalysis` 和 `report.highEarnerTraits`(或置空);前端 VipOverlay 改成纯占位"开通 VIP 解锁",不再期待真实数据。
- **为什么不在 D3 直接改**:① 这是前后端协同改动(后端删字段→前端遮罩处要改成空占位,否则白屏);② A500 新后端尚未部署(线上仍是旧纯前端版),属于 Week2 A500 上线范畴;③ 涉及"VIP 到底卖什么"的产品判断,需用户拍板。→ 列入 Week2 A500 上线前一并改。

## 已确认安全项
- `/api/me/history/salary/:id`(server.js:121)有 `getReportByIdForPhone(id, phone)` 归属校验,不能看他人报告 ✓
- 自实现 body parser 有 1MB 上限 + 413 保护(server.js:46),JSON 解析失败返 JSON 而非默认 HTML(有意绕线上 nginx 坑)✓
- 缓存命中按 5 项条件全等,不串用户 ✓

## 旁注(P3,不改)
`app.set("trust proxy", true)`(server.js:34):A500 无自己的限频(登录在中心),`req.ip` 仅用于入库记录,不参与任何鉴权,所以伪造 X-Forwarded-For 在 A500 无安全后果——仅入库 IP 失真。建议未来统一改 `1` 保持矩阵一致,但非安全项,本次不动。
